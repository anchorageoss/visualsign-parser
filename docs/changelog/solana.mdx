<Update label="2026-11-05 — Abra preset and shared receipt-token rendering" tags={["Wallet API", "Contributors"]}>
  The Abra programs now get per-operation views: `mint`, `request_unmint`, `claim_unmint`, and `cancel_unmint` on the backed-token program, and `stake`, `request_unstake`, and `claim_unstake` on the liquid-staking program. Each operation gets a title, a typed amount, and a row that checks the destination is the signer's own token account or, for a request, the escrow of the signer's own request account. No received amount is estimated: it depends on the exchange rate at execution. The other instructions keep the generic IDL view.

  The Jupiter Lend Earn preset and the Abra preset now share one renderer, `core::receipt_token`, for programs where the signer supplies an asset, receives a receipt token, and later redeems it. A new preset of this shape declares its program ID, IDL, account names, and one entry per instruction; decoding, amount formatting, recipient checks, both layouts, and the transaction summary are shared. Jupiter Lend Earn output is unchanged.
</Update>

<Update label="2026-11-05 — Abra IDLs" tags={["Wallet API", "Contributors"]}>
  The IDLs of the two Abra programs on Solana are now compiled in: the backed-token program `H9Cyw2RRHStwtKTAgGPm3nU48xwQ2Scy8u2gjg82dyQQ` (USDC mints USDaf) and the liquid-staking program `9cYNMhVvGC2LhgJYZavKVWYZ8T1oqSHYt5ehTddP51yC` (USDaf stakes into sUSDaf). The intermediate output decodes every instruction of both programs with `registered_source = Preset`; the human-readable view still shows them as an unknown program until their preset lands.

  A program whose IDL is compiled in ahead of its preset is now registered and trusted like a preset program: a caller-supplied `idl_mappings` entry for it is ignored and the bundled IDL is used instead.
</Update>

<Update label="2026-10-18 — Solana packet-size gate" tags={["Security"]}>
  Solana transactions over `PACKET_DATA_SIZE` (1232 bytes) are now refused before decoding, on both the string and the SDK-type entry points. Nothing valid on-chain is larger, and each account index in an oversized blob expanded ~50x into the intermediate output and again into the payload (#551).
</Update>

<Update label="2026-06-12 — Drift Protocol preset" description="v0.769.0" tags={["Wallet API", "Contributors"]}>
  VisualSign now decodes Drift Protocol instructions. Like every Solana preset, it ships as a self-contained directory under `src/chain_parsers/visualsign-solana/src/presets/` with no changes to existing decoders. See [Adding a Solana preset](/chains/solana).
</Update>

<Update label="2026-05-30 — Solana decoder hardening" description="v0.722.0 — v0.730.0" tags={["Security"]}>
  A round of safety fixes on the Solana path: caller-supplied IDL overrides are rejected for trusted programs and validated against the signer allowlist, V0 transactions referencing unresolved address-lookup-table entries are rejected instead of mis-decoded, `swig_wallet` inner-instruction recursion is depth-bounded, and Token-2022 mints with more than 18 decimals are rejected while `format_token_amount` gained overflow hardening.
</Update>

<Update label="2026-05-12 — Solana preset wave" description="v0.646.0 — v0.649.0" tags={["Wallet API", "Contributors"]}>
  VisualSign now decodes Jupiter (Borrow, Earn, Perpetuals, v6 route_v2), Kamino (Borrow, Vault, Farms, Limit Orders), Meteora (DLMM, DAMM V2), MetaDAO (Futarchy, Conditional Vault), Orca Whirlpool, Onre App, Neutral Trade, DFlow Aggregator, and Exponent Finance.

  None of these additions required changes to existing decoders or to the core parser. Each preset is a self-contained directory under `src/chain_parsers/visualsign-solana/src/presets/`, auto-registered by `build.rs`. See [Composable by design: how Solana presets stack](/blog/2026-05-13-composable-solana-presets) for the architecture, and [Adding a Solana preset](/chains/solana) for the how-to.
</Update>

<Update label="2026-05-12 — Surfpool mainnet-fork integration for IDL fuzz testing" description="v0.647.0" tags={["Contributors"]}>
  The built-in Solana IDL parser path is now fuzz-tested against real mainnet state via Surfpool. Tests run against a local mainnet fork backed by live RPC, so they catch drift between IDL assumptions and on-chain reality without broadcasting to a live cluster.
</Update>
