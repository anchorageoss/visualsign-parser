title: Cosmos
description: Cosmos SDK sign docs in direct (protobuf) and Amino JSON modes
---

The Cosmos module decodes the bytes a Cosmos SDK signer is asked to sign and renders them as a VisualSign payload. It works for any Cosmos SDK chain; the chain is identified by the `chain_id` inside the sign doc, so there is no network flag or chain metadata.

## Architecture overview

### Transaction model
- **Input is the sign doc, not the broadcast transaction.** The signer approves the exact bytes it signs, so those are what is decoded.
- **`SIGN_MODE_DIRECT`**: the protobuf `SignDoc { body_bytes, auth_info_bytes, chain_id, account_number }`, as hex (optional `0x` prefix) or base64. A broadcast `TxRaw` is not a `SignDoc` and is rejected.
- **`SIGN_MODE_LEGACY_AMINO_JSON`**: the `StdSignDoc` JSON exactly as signed (keys sorted, no whitespace, Go string escaping). Input that is not byte-identical to that canonical form is rejected, so the document shown is the document signed.
- **Fail closed**: in direct mode each layer (`SignDoc`, `TxBody`, `AuthInfo`) must re-encode to exactly its input bytes. A layer with fields the parser does not model is refused. So is any modeled message carrying unmodeled fields (for example an ibc-go v9 `MsgTransfer` with `forwarding`), since those fields could move funds that would not be displayed. `MsgTransfer` renders both the deprecated `token` and the ibc-go v9 `tokens`.

### Dependencies
The protobuf messages are hand-written `prost` structs. The crate does not depend on `cosmrs` or the Cosmos SDK protos.

## SDK compatibility

Compatibility is selected by wire/message shape, not a latest-SDK gate. Historical Amino bank/staking layouts and governance option strings are retained alongside ordinary protobuf Direct transactions. The shared fixture corpus covers tagged schema families from v0.30 through v0.55. Historical delegation shares are shown as shares, never token amounts; ambiguous mixed-era schemas reject.

See [the compatibility matrix and exact limits](../cosmos-sdk-compatibility.md), including fixture provenance and unsupported signing modes. The v0.55 ML-DSA key type does not limit classical transaction parsing to that SDK version.

## Supported messages

| Message | Direct type URL | Amino type | Fields surfaced |
|---|---|---|---|
| Bank send | `/cosmos.bank.v1beta1.MsgSend` | `cosmos-sdk/MsgSend` | From, To, Amount |
| Delegate / Undelegate | `/cosmos.staking.v1beta1.MsgDelegate`, `MsgUndelegate` | `cosmos-sdk/MsgDelegate`, `MsgUndelegate` | Delegator, Validator, Amount |
| Redelegate | `/cosmos.staking.v1beta1.MsgBeginRedelegate` | `cosmos-sdk/MsgBeginRedelegate` | Delegator, From Validator, To Validator, Amount |
| Withdraw rewards | `/cosmos.distribution.v1beta1.MsgWithdrawDelegatorReward` | `cosmos-sdk/MsgWithdrawDelegationReward` | Delegator, Validator |
| Gov vote | `/cosmos.gov.v1beta1.MsgVote`, `/cosmos.gov.v1.MsgVote` | `cosmos-sdk/MsgVote`, `cosmos-sdk/v1/MsgVote` | Proposal, Voter, Option, Metadata |
| Authz exec | `/cosmos.authz.v1beta1.MsgExec` | `cosmos-sdk/MsgExec` | Grantee and each inner message |
| IBC transfer | `/ibc.applications.transfer.v1.MsgTransfer` | `cosmos-sdk/MsgTransfer` | Sender, Receiver, Amount, Channel, timeouts, Memo |
| Wasm execute | `/cosmwasm.wasm.v1.MsgExecuteContract` | `wasm/MsgExecuteContract` | Sender, Contract, contract-defined JSON message, Funds |

Authz `MsgExec` is decoded recursively up to three levels deep; deeper nesting is refused. Any other message renders as `Type: <type_url> (not fully decoded)` plus its raw `Value`.

Each sign doc also shows `Chain ID`, `Account Number`, `Memo`, timeouts, `Fee`, `Gas Limit`, fee payer and granter, and for every signer the public key, sign mode and sequence. Public keys are recognised for secp256k1, ML-DSA-65 (`/cosmos.crypto.mldsa65.PubKey`, shown as its length and SHA-256), and legacy Amino multisig (threshold and members). Any other key type is shown by its type URL.

## Visualization strategy

- **Amounts stay in the base denomination** (`1000000 uatom`). Cosmos denoms carry no fixed decimals, and IBC denoms (`ibc/...`) cannot be resolved without chain state, so no conversion is guessed.
- **Contract messages are shown, not explained.** The contract interprets its JSON message, so the parser shows it verbatim and labels it contract-defined.
- **Unknown content is visible.** Unknown message types, extension options, key types and unrecognised Amino fields are shown rather than dropped.
